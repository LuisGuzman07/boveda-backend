# CU-20 Emergency Kit

The Emergency Kit is a client-generated recovery artifact for one vault. The browser or mobile client derives an Argon2id key from the kit password and encrypts the in-memory 32-byte vault key with AES-256-GCM. The exported JSON contains only that authenticated envelope, the Argon2id parameters and salt, a version, an expiry, and a SHA-256 fingerprint.

## Backend contract

- `POST /api/v1/vaults/{vault_id}/emergency-kit` stores or replaces the active envelope. It requires the current authenticated vault session, MFA-backed session, trusted device, active vault membership, and `EMERGENCY_KIT_ENABLED` policy.
- `GET /api/v1/vaults/{vault_id}/emergency-kit` returns the active encrypted envelope and metadata. It never returns a vault key or password.
- `POST /api/v1/vaults/{vault_id}/emergency-kit/recover` accepts an active kit id and a device-wrapped vault envelope produced locally on the current trusted device. The server stores the wrapper without decrypting it.
- `POST /api/v1/vaults/{vault_id}/emergency-kit/revoke` revokes the active kit. Replacement revokes the previous version first.

All lifecycle attempts are audited with action, result, device, vault, kit version, and fingerprint only. Passwords, plaintext keys, file keys, original files, and kit ciphertext contents are not written to audit details.

## Cryptography

Version 1 uses the existing project parameters: Argon2id, 64 MiB memory, three iterations, one lane, 32-byte output, a fresh 16-byte salt, and AES-256-GCM with a fresh 12-byte nonce and 16-byte tag. The vault id and purpose are authenticated as AAD. No custom cryptography or backend decryption is introduced.

## Limitation

Browser device-wrapping keys remain subject to the browser's local storage security model; this implementation does not claim hardware-backed browser security. Recovery still requires the existing authenticated, MFA-backed, device-bound vault session and a device in `TRUSTED` state. The current project enrollment flow is the authority for that trust state; CU-20 does not invent a new out-of-band approval mechanism.
