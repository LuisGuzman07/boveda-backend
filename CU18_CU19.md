# CU-18/CU-19 encrypted temporary sharing and revocation

`acceso_compartido` retains a grant and its audit provenance. A grant has exactly one scope: a vault or a file. `sobre_acceso_compartido` contains recipient-device encrypted envelopes only; the API never accepts or derives vault or file plaintext keys.

The grantor must own the scope and have `files:share`. The recipient must be active and every envelope target must be a registered `TRUSTED` device with a public identity. The server enforces start time, expiry, active state, device match, and scope for recipient metadata and download access. File-only grants use a constrained query and never use `VaultRepository.get_owned`.

Revocation retains audit records, marks grants and envelopes revoked, and revokes recipient application and vault sessions. It blocks future API access immediately. It cannot remove ciphertext or plaintext previously downloaded or decrypted offline. `epoca_clave` and `version_clave` provide prospective rotation metadata; this unit does not perform universal destructive re-encryption.

The web UI creates, lists, and revokes grants. It requires an envelope created locally for the recipient identity; the server stores it opaquely. Mobile is intentionally API/read-only for CU-18/CU-19 and has no sharing-management UI in this unit.
