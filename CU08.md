# CU-08: encrypted file upload

The client generates a random 32-byte AES-256-GCM key and 12-byte nonce for
each file version. It encrypts the file locally, computes SHA-256 over the
ciphertext bytes, and wraps the per-version key with the active vault key
using AES-256-GCM. The API receives the ciphertext, encrypted filename,
wrapped file key, nonce/tag metadata, size, and hash only.

`ClaveEnvuelta` is reused for file-key envelopes by associating the row with
`VersionArchivo.id_version_archivo`. Existing vault-key rows remain associated
only with the vault and are selected with `id_version_archivo IS NULL`.

The signed vault-session request is `POST /api/v1/vaults/{vault_id}/files`.
The request body is JSON so the existing Ed25519 body digest contract remains
unchanged. MinIO object keys contain only UUIDs and fixed path segments.

CU-09 listing, CU-10 download/decryption, S3 replication, consistency checks,
and Emergency Kit recovery are intentionally outside this change.
