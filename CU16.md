# CU-16 Administrative User RBAC

The administrative API is available under `/api/v1/admin` and uses database-resolved permissions as its authorization source:

- `users:read`: paginated user listing and read-only role/permission catalogs.
- `users:update`: activate or deactivate a different user with an audited reason.
- `users:assign_role`: assign or remove a seeded role from a different user with an audited reason.

The service rejects self-administration, duplicate or unknown roles, privilege escalation, and removal or deactivation of the final active administrator. Authorization changes revoke the target user's application sessions, refresh families, and vault sessions. Access tokens presented after that revocation are rejected by the existing server-side session validation, rather than remaining usable until their JWT expiry.

The web client provides the CU-16 administration modal. Mobile intentionally has no administrative surface in this work unit; the backend contract remains available to any authorized client.
